# Internationalization

Supported language codes: en, de, sk, hu, es. Normalize the legacy/requested `esp` alias to `es`.

Shared runtime: packages/platform/src/i18n.ts. React components use useI18n or TranslatedText from @sorye/platform/react. Use explicit translation keys; never translate user records, document contents, API identifiers, or stored workflow values automatically. Use Intl with the selected locale for presentation of dates and numbers.

Language selection is a browser preference in sorye:locale localStorage. Same-document events synchronize independently bundled apps; storage events synchronize tabs. Storage failure must not prevent selection. Server rendering defaults to English for hydration stability. External SUSM/ESPM services own their translations.

Current coverage: shared common action labels and Hub language selector. App-specific copy, validation messages, and date/number presentation remain to be migrated. Landing pages are translated in all five languages. Do not describe the product as fully translated until those are covered and tested.

Every new UI message must supply all five translations. Every app landing-page change must update all translated variants once introduced.

Public landing entry URLs negotiate Accept-Language with quality weights and regional tags. Explicit locale URLs remain authoritative. Detection uses browser language preferences, not geographic location or IP lookup. Redirects are private and no-store so caches cannot share a visitor’s language choice.
