Sorye app behavior tree

Static reference for how a user moves through the Hub, how apps reach their handlers, where data is stored, and how OCR hands a matrix to Protocolio.

How to read it: arrows name the route or action that connects nodes. Node IDs match the handler index below each diagram. The diagrams are static SVG; this file has no scripts, controls, or external dependencies.

1. Open an app and retain its state

Hub resolves identity and workspace before showing the catalog. Apps can be Hub-native, Module Federation remotes, or external iframe apps. Pane state and app-private state have different owners and lifetimes. Background state reads pause in hidden/offline tabs: notifications update on events with a 60-second safety refresh; standalone workspace state refreshes on focus/reconnect with a five-minute safety refresh. Event bursts are coalesced and requests do not overlap. Qwen analysis uses separate analyze/continue requests.

2. App requests, events, and handoffs

Apps use authenticated Hub APIs for shared data. The kernel gives each remote a constrained client. Hub validates input and workspace scope before a service/store handles it.

3. OCR matrices, Node analysis, and Protocolio

OCR has two reading paths: a browser matrix path for review/comparison/export and a Node PDF.js path that normalizes meaningful body rows into one continuous three-column table. Filename, stored ID and PDF type identify the document; unclear findings follow the data. The browser sends a selected matrix to Protocolio through a workspace handoff.
